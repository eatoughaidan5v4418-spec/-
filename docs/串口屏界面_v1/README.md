## 2. 设计原则

1. **屏内不放逻辑。** 屏幕工程里只有控件、图片和每个触摸事件里的一行 `printh`。显示哪一页、每个控件显示什么，全部由主控决定。这样界面行为只有一份代码，换屏或改流程时不用同时改两边。
2. **屏幕不自己翻页。** 用户点了按钮，屏幕只上报；主控判断后再下发 `page` 指令。
3. **只发变化的值。** 主控记着每个控件上次发的值，没变就不发。换页或屏幕重启后全部重发。
4. **心跳对齐。** 每一页有一个 1 秒定时器上报当前页号。页号和主控认为的不一致（例如屏幕被单独复位），主控就整页重画。

## 3. 页面和控件

每个控件的位置和尺寸见 [控件坐标.md](控件坐标.md)，那是脚本从原型量出来的，和导出的图片逐像素对应。图片和按钮控件必须严格按表放；文本和数字控件给的是文字的实际范围，控件可以做宽一些。控件名固件里写死了，**不能改名**。

文本和数字控件的背景设置：

- main 页右侧面板上的（nFree、tTot、tSel、tJob、tStep、tIdx、nEta）：背景选纯色，颜色 `#0E1626`（RGB565 = 2212），和面板底图同色。
- main 页标题栏的 tClk、fault 页的全部文本：背景选“切图”，切图图片填该页的背景图编号（main 填 0，fault 填 1）。
- 其余页面是纯色背景，文本背景用同一个颜色。

所有页面都要加一个定时器 `tmHb`（1000 ms，启用），定时事件里写该页的心跳帧，见第 5.2 节。

左侧车位图，8 个车位各一个图片控件，按方位固定顺序命名：

| 控件 | 方位 | 类型 | 按下事件 |
|------|------|------|----------|
| b0 | 东 | 图片 | `printh A5 11 00 00 11 5A` |
| b1 | 东北 | 图片 | `printh A5 11 01 00 12 5A` |
| b2 | 北 | 图片 | `printh A5 11 02 00 13 5A` |
| b3 | 西北 | 图片 | `printh A5 11 03 00 14 5A` |
| b4 | 西 | 图片 | `printh A5 11 04 00 15 5A` |
| b5 | 西南 | 图片 | `printh A5 11 05 00 16 5A` |

### 重新导出

改了原型的样式或布局后重新运行脚本，素材、预览图和坐标表会一起更新：

```bash
py tools/export_hmi_assets.py
```

脚本用本机的 Edge 或 Chrome 无头渲染原型，需要先装 `playwright` 和 `pillow` 两个 Python 包。它最后会做两项自检：车位状态变化是否都落在车位矩形内；用导出的小图重新拼出主页，和直接渲染的画面逐像素比较。当前结果是两项都为 0 个差异像素。

## 5. 通信协议

### 5.1 帧格式

**屏幕 → 主控**，固定 6 字节，在触摸事件里用 `printh` 发出：

```
A5  CMD  P1  P2  SUM  5A        SUM = (CMD + P1 + P2) 取低 8 位
```

所有事件的参数都是常量，所以每个控件的 `printh` 后面直接写死 6 个字节，屏幕不用算校验。

屏幕自己还会发一些原生返回（以 `FF FF FF` 结尾），主控只处理这几种：

| 首字节 | 含义 | 主控处理 |
|--------|------|----------|
| `88` | 屏幕启动完成 | 整页重画 |
| `00 00 00` | 屏幕上电 | 整页重画 |
| `02`～`24` | 指令执行失败 | 记一条警告日志，通常是控件名或图片编号在屏幕工程里不存在 |

**主控 → 屏幕**，用屏幕原生指令，ASCII 文本，中文为 GB2312，以 `FF FF FF` 结尾。用到的指令只有这几种：

```
page 1                  切换页面
b2.pic=20               改图片
nFree.val=10            改数字
tStep.txt="送入车位"     改文字
jOcc.bpic=85            改进度条底图（ppic 为填充图）
bOk.pic2=67             改按钮按下时的图
s1.bco=9885             改背景色（pco 为文字色）
vis bStore,0            隐藏 / 显示控件
tsw bOk,0               禁用 / 启用触摸
dim=30                  背光亮度
```

| sen | `printh A5 01 08 00 09 5A` |

### 5.3 主控一侧的保护

屏幕上报的事件只是“用户想做什么”，主控会再核对一遍才执行：

- 出入口红外被挡时，“确认存车”和“已取走”按钮禁用，就算收到这两个事件也不执行。
- 故障回零必须两项都勾上。
- 只有就绪状态才接受存车、取车和进维护。
- 待机时的第一次触摸只唤醒，不执行任何操作。
- 3.5 秒收不到心跳，主控记一条“屏幕离线”日志；车库的动作不受影响。

## 6. 屏幕工程搭建步骤

### 6.1 新建工程

1. USART HMI 上位机新建工程，型号选 TJC4827T143_011C，方向横屏 0°，**字符编码选 GB2312**。
2. 在 `Program.s`（工程初始化脚本）里写：

```
bauds=115200
bkcmd=2
page 0
```

`bkcmd=2` 表示只在指令失败时返回，主控靠它发现控件名写错。

3. 所有控件的“发送键值”保持不勾选，触摸只通过 `printh` 上报。

### 6.2 导入图片

把 `素材/` 里的 93 个文件按文件名排序后一次导入，导入后核对最后一张（`92_pin_full.png`）的编号是 92。

### 6.3 生成字库

| 字库编号 | 字高 | 内容 | 用途 |
|----------|------|------|------|
| 0 | 16 | 全部 ASCII + [字库字符集.txt](字库字符集.txt) 里的汉字 | 小字、提示 |
| 1 | 24 加粗 | 同上 | 标题、步骤名 |
| 2 | 40 | 数字 0～9 | 剩余秒数、待机空位数 |
| 3 | 60 | 数字 0～9 | 主页空位数 |
| 4 | 84 | E 和数字 0～9 | 故障码 |
| 5 | 120 | 数字 0～9 和冒号、减号 | 待机大时钟 |

`字库字符集.txt` 是脚本从固件文字表生成的，目前 165 个字。只收用到的字，字库很小；以后在 `hmi_text.txt` 里加了新字，要重新生成字库再下载到屏幕，否则新字显示成空白。

### 6.4 建页面

按第 3 节建 9 个页面，页面顺序决定页号。每页加 `tmHb` 定时器和对应的心跳帧。

### 6.5 联调顺序

上位机的“调试”功能可以用电脑串口直接连主控，不用下载到屏幕就能看效果，建议先这样调通再烧屏。

1. 只建 boot 和 main 两页，确认上电后屏幕从 boot 跳到 main，说明双向通信通了。
2. 在 msh 里运行 `hmi_stat`，看到 `screen online` 和正确的页号。
3. 补齐其余页面。每加一页，在 msh 日志里看有没有“screen rejected an instruction”，有就是控件名或图片编号对不上。
4. 用 `sim_fault 12`、`sim_estop 1`、`sim_estop 0` 触发故障页和急停页。

## 7. 固件

### 7.1 文件

都在 `firmware/spark_garage_lvgl/applications/hmi/`：

| 文件 | 作用 |
|------|------|
| `ui_model.h` | 界面和调度之间的接口：一个状态快照结构、一组命令、三个函数 |
| `hmi_proto.h/.c` | 帧解析，不依赖 RT-Thread |
| `hmi_res.h` | 页号和图片编号 |
| `hmi_text.txt` | 主控下发的全部中文（UTF-8），**改文字只改这里** |
| `hmi_text.h` | 脚本生成的 GB2312 字节表，不要手改 |
| `hmi_tjc.c/.h` | 串口屏后端：收发线程、页面决策、差量刷新 |
| `ui_sim.c` | 假车库，调度模块写好后删除 |

改了 `hmi_text.txt` 后运行：

```bash
py tools/gen_hmi_text.py
```

### 7.2 调度模块怎么接

调度模块只需要实现 `ui_model.h` 末尾的三个函数，然后删掉 `hmi_tjc.h` 里的 `HMI_USING_SIM`：

- `garage_ui_get_state()`：填一份当前状态（阶段、车位表、转运台位置、任务步骤、故障码、传感器、各轴位置）。界面线程每 100 ms 调一次，不能阻塞。
- `garage_ui_post_cmd()`：接收存车、取车、确认、取消、回零、点动、标定保存等命令，一般是丢进调度的消息队列。
- `garage_ui_get_cal()`：读某个车位已保存的标定值。

板载屏的 LVGL 调试界面（`garage_ui.c`）目前还是自己内部模拟，没有改成走这套接口。

故障码和步骤名是我先拟的（见 `hmi_text.txt`），调度模块实现时可以增删，改完重新生成文字表即可。

### 7.3 串口配置和 msh 命令

这次在 `rtconfig.h` 和 `.config` 里打开了 `BSP_USING_UART3`。如果以后在 RT-Thread Studio 的设置界面里重新生成配置，确认 UART3 还勾着。

| 命令 | 作用 |
|------|------|
| `hmi_stat` | 屏幕是否在线、当前页号、丢弃的坏帧数 |
| `hmi_pin 1234` | 改维护密码。只存在内存里，复位后恢复默认值 `0000` |
| `sim_fault <故障码>` | 假车库：触发故障 |
| `sim_estop <0\|1>` | 假车库：按下 / 松开急停 |

## 8. 要在实机上确认的事

这些地方我是按屏幕手册的说明写的，没有真屏验证过：

1. **隐藏控件后的重画。** 面板切换时主控先隐藏全部面板控件，再换 pPanel 的图，再显示本模式的控件。如果实机上出现残影或控件被底图盖住，需要调整这三步的顺序，改 `hmi_tjc.c` 的 `panel_switch()`。
2. **图片模式进度条**的 `bpic`、`ppic` 能否在运行时修改；不能的话 14 格和 7 格的占用条要做成两个控件。另外占用条是按百分比填充的，格子边界可能差 1 像素。
3. **按钮禁用**后（`tsw bOk,0`）外观是否保持禁用图。
4. **文本换行**：`tStep`、`tDesc` 要打开多行；提示里的换行写的是 `\r` 两个字符，确认屏幕把它当换行处理。
5. **切页闪烁**：main 页每次进入要发 40 条左右指令，115200 波特率下约 60 ms，看是否能接受。
6. **点阵字的观感**：T1 系列字库没有抗锯齿，24 号加粗和 120 号大数字的实际效果要看了再定是否换字体。
7. **Flash 容量**，见第 4 节。
8. **图片色彩**：素材是 24 位色 PNG，上位机导入时转成 16 位色。深色渐变背景可能出现轻微色带，面板纯色和文本背景色是否完全一致也要看实机；有色差就把文本控件背景改成“切图”。

## 9. 和计划书不一致的地方

- 计划书 4.8 节写进度页有取消按钮。本方案把取消放在放车前的出入口确认页，进度页不提供取消，只提示按急停，理由是 4.6 节规定运动中不中断。定稿时计划书这一句要改，或者在这里加回取消键。
- 计划书把主页、进度、故障、维护列为 4 个页面；实际做成 9 个屏幕页面，其中主页、已选、出入口确认、进度共用一个 main 页。
