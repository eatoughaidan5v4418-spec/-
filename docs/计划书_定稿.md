## 1 项目概述与需求分析

### 1.1 背景与问题

城市停车用地紧张，机械式立体车库通过竖向叠放提高单位面积的停车数。常见的升降横移式车库，每个车位或每列托盘都需要配备电机、限位和驱动器，运动轴数随车位数线性增加。这带来三个问题：

1. **成本和故障点随规模增加**：车位越多，电机、驱动、线缆和传感器越多，任何一处失效都可能影响整机。
2. **扩容困难**：增加一层需要同时增加机构、布线和控制程序，通常要重新调试。
3. **调度与安全逻辑分散**：多个运动轴并行时，互锁条件复杂，难以证明不会发生碰撞或误动作。

### 1.2 本作品思路

本作品把所有运动集中到塔中心的一台**升降转运装置**上。每层只是无电机的环形车位架，8 个车位按 45° 辐射排列。整机只有 3 个运动轴：**升降 Z、旋转 θ、转运拨叉 u**。层数增加时，运动轴数量不变。

用户只在一层前侧的 **DOCK（交接位）** 放车、取车。系统自动把空托盘调到 DOCK，或把目标车辆所在的托盘取到 DOCK。

### 1.3 需求摘要

| 类别 | 要求 |
|------|------|
| 容量 | 两层，每层 8 个方位。一层的前侧方位为 DOCK，二层同方位留空作为 DOCK 上方竖井，共 **14 个存车位** |
| 结构 | 运动件全部集中在中央升降塔；层模块无电机，可整层加装 |
| 人机 | 4.3 寸电容触摸串口屏为人机界面，支持存车、取车、取消、状态显示和故障提示 |
| 调度 | 车位表按（层，方位）编址；按代价选位；DOCK 空托盘预置；优先级为急停 > 取车 > 存车 > 后台预置 |
| 安全 | 硬件急停只切断电机支路；Z 轴上下硬限位；DOCK 红外对射防手入；软件互锁覆盖每一步动作 |
| 平台 | 星火一号 / STM32F407，**必须使用 RT-Thread 标准版** |
| 演示 | 存车、取车、空托盘预置、取消存车、急停恢复、自动识别层数；初赛视频不超过 5 分钟、500 MB |

### 1.4 设计目标

1. 3 个电机完成两层 14 个车位的全部存取动作，并证明层数增加时不需要增加电机。
2. 在 RT-Thread 上实现带优先级的任务调度和分层安全互锁，任何异常都进入可人工确认的安全状态。
3. 上电时自动识别层数，车位表和标定表按层生成，加装第二层时只需补录标定数据。
4. 一层样机在加装第二层之前完成连续存取的可靠性测试。

## 2 单片机参数与选型

### 2.1 主控芯片主要参数

星火一号板载 **STM32F407ZGT6**（LQFP144）。

| 参数 | 指标 | 本作品用途 |
|------|------|------------|
| 内核 | ARM Cortex-M4F，带单精度 FPU 和 DSP 指令 | 梯形加减速曲线、代价计算 |
| 主频 | 最高 168 MHz | RT-Thread 多线程和高频步进脉冲 |
| Flash / SRAM | 1 MB / 192 KB（含 64 KB CCM） | 程序、车位表、任务队列、日志缓冲 |
| 定时器 | 2 个高级定时器、10 个通用定时器、2 个基本定时器 | 3 路步进 STEP 脉冲、超时监控 |
| 通信 | 多路 USART、3 路 I²C、3 路 SPI、CAN、USB OTG | 串口屏（USART3）、层检测板（I2C1）、板载 Flash |
| GPIO | 多数引脚为 5 V 容忍（FT），支持外部中断 | 方向 / 使能、限位、急停状态；5 V 霍尔和红外直接接入 FT 引脚 |
| 调试 | SWD；板载 ST-LINK | 在线调试与下载 |

### 2.2 开发板板载资源

| 资源 | 本作品用途 |
|------|------------|
| SPI NOR Flash | 保存每个车位的标定表、车位表快照和故障日志 |
| 板载 240×240 LCD、方向键 | 开发阶段的调试界面，不作为作品的人机界面（见 4.8） |
| LED、蜂鸣器 | 运行指示、故障声音提示 |
| RW007 WiFi 模块 | 可选扩展：远程查看车位状态（不作为初赛必备功能） |
| 40Pin 排针、两组 PMOD | 经自制转接板引出 STEP / DIR / EN、I²C、USART 和检测信号 |

### 2.3 选型依据

1. **定时器资源充足**：3 台步进电机需要独立的 STEP 脉冲和加减速控制。F407 的高级 / 通用定时器足够分配，同时还能留出定时器做运动超时监控。
2. **算力和内存余量**：需要同时运行人机、调度、运动、安全监测 4 个以上线程，维护车位表、任务队列和标定表。168 MHz 主频和 192 KB SRAM 能满足需要，并为日志和后续扩展留出空间。
3. **板载外部 Flash**：标定表要掉电保存，加层后需要追加。板载 SPI Flash 配合 RT-Thread 的 FAL 组件即可分区管理，不需要外接存储。
4. **RT-Thread 官方支持**：星火一号是 RT-Thread 官方开发板，BSP 和设备驱动完善，可以把精力集中在调度和安全逻辑上。
5. **符合赛项**：方向三指定的传统 ST 选题平台。

### 2.4 为什么使用 RT-Thread 标准版

| 需求 | 裸机主循环的困难 | RT-Thread 标准版的做法 |
|------|------------------|------------------------|
| 急停和光电必须及时响应 | 主循环中的阻塞会延迟响应 | 安全监测线程设为最高优先级，由中断释放信号量唤醒 |
| 用户操作不能阻塞运动 | 屏幕通信和运动混在一起 | 人机、调度、运动线程解耦，通过消息队列传递命令 |
| 多种外设 | 驱动各自实现，难以复用 | 使用 PIN、I²C 总线、串口、PWM / 硬件定时器等设备框架 |
| 标定和调试 | 每次修改都要重新烧录 | 通过 FinSH / msh 命令行点动、标定和读写参数 |
| 掉电保存 | 需要自己管理 Flash 擦写 | FAL 分区 + 键值数据库软件包 |

## 3 硬件规划

### 3.1 系统组成

```text
                          ┌──────────── 星火一号 STM32F407ZGT6 ────────────┐
 TJC 4.3 寸串口屏 ◄─USART3─┤                                                │
                          │ TIM1 / TIM2 / TIM4 → STEP    GPIO → DIR×3、EN×3  ├─► TMC2209 ×3 → 升降 / 旋转 / 转运步进
 一层检测板 MCP23017 0x20 ◄┤ I2C1                                           │
 二层检测板 MCP23017 0x21 ◄┤                                                │
                          │ GPIO / EXTI ← Z 回零、Z 上下限位监测、θ 原点霍尔、 │
                          │   拨叉两端、转运台霍尔、DOCK 红外 ×2、急停状态     │
                          │ SPI Flash ← 标定表 / 日志                        │
                          └────────────────────────────────────────────────┘
 每块层检测板：8 路霍尔输入（车位有无托盘）+ 8 路指示 LED 输出
```

驱动器和 I/O 扩展芯片都采用现成模块，插在自制的转接 PCB 上：主转接板叠装在星火一号 40Pin 排针上，承载升降、旋转两路驱动和全部检测接口；副转接板插在两组 PMOD 上，承载转运驱动和串口屏接口；每层一块相同的层检测板。

### 3.2 机械结构

| 部分 | 设计 |
|------|------|
| 外框 | 500×500 2020 铝型材框架，四角立柱高 270 mm，底板 520×520×6 |
| 层模块 | 2020 环梁 + 对角斜撑 + 5 mm 激光切割亚克力甲板。甲板中心开 R102 井孔，以及定位销槽、支撑臂槽和竖向件让位口。层高：一层 Z=100，二层 Z=190 |
| 车位 | 每层 8 个方位，托盘 125×60×3，长边沿径向。每个车位有侧导条、端挡，甲板下有 1 个霍尔传感器、1 个指示 LED |
| 托盘 | 底部装 Φ4 定位销（伸出 5 mm，距内端 7 mm）和 1 块磁铁，内端两角 C10 倒角，用于让开升降平台的支撑臂 |
| 升降 | NEMA17 + T8 丝杆（单头，导程 2 mm）+ 2 根 Φ8 光轴配 LM8LUU；顶端 KFL08 支承 |
| 旋转 | NEMA17 吊装在升降平台下方，直接驱动转运台，3 寸转盘轴承承载；转角限制在 −135°…+180°，线缆只往返不连续旋转 |
| 转运 | 170 mm MGN7 导轨 + NEMA11 + GT2 皮带，滑块带 U 形拨叉，行程 138 mm |

### 3.3 关键机构：用升降代替抓取执行器

转运台上没有电磁铁、舵机或直线执行器。拨叉与托盘销的**啮合和脱开完全靠升降轴上下 8 mm 完成**：

| 状态 | 转运台面高度 | 拨叉与销的关系 |
|------|--------------|----------------|
| 啮合高度 | 与甲板齐平（Z_L） | 销伸入 U 形拨叉 4 mm |
| 脱开高度 | Z_L − 8 | 拨叉在销下方，间隙 4 mm |

- **取托盘**：拨叉收回 → 旋转对准 → 降到脱开高度 → 拨叉伸到销下方 → 上抬 8 mm 啮合 → 拨叉拉回，托盘滑上转运台。
- **送托盘**：在啮合高度推出 → 下降 8 mm 脱开 → 拨叉空载收回。

三维模型校核结果：转运台旋转时最外侧的皮带包络为 R98.5，井口为 R102，留有约 3.5 mm 余量；拨叉在全行程（含两端越程）内与带轮的连续包络间隙不小于 0.99 mm；升降、旋转、推拉各姿态的离散采样未发现干涉。以上是名义尺寸下的模型校核，托盘跨越交接缝的顺畅程度和拨叉入销的可靠性将在一层样机上通过试验确认。

### 3.4 电源与安全回路

```text
12 V / 5 A 适配器（机内不引入市电）
 ├─ 逻辑支路：12→5 V（3 A）→ 星火一号、串口屏；星火 5 V → 霍尔、红外；星火 3.3 V → 驱动逻辑、MCP23017
 └─ 急停常闭 + Z 上下硬限位常闭 → 继电器自保持 / 手动复位 → 电机 12 V 支路 → TMC2209 ×3
```

| 项目 | 方案 |
|------|------|
| 急停 | 硬件切断电机支路；主控和屏幕保持供电，用于显示状态、记录日志 |
| 硬限位 | Z 上下限位的常闭触点串在电机支路中，另有一组触点由 GPIO 监测，软件可以得知是哪一路断开 |
| 复位 | 继电器自保持，必须手动按复位键才能恢复电机供电，不会自动重启运动 |
| 电流 | 三台步进同一时刻只允许一台运动，按驱动限流约 1 A 估算，12 V 支路峰值输入约 2 A，电源留有一倍以上余量 |
| 防护 | 保险丝、驱动器附近的储能电容；电机动力电流不经过开发板排针，逻辑地与电机地共参考 |

## 4 设计方案

### 4.1 软件总体架构

```text
┌────────────── 应用层 ──────────────┐
│ 人机线程   调度线程   运动线程   安全监测线程 │
├────────────── 服务层 ──────────────┤
│ 车位表 / 标定表（FAL + 键值数据库）  任务队列  ulog 日志  msh 调试命令 │
├────────────── 驱动层 ──────────────┤
│ 步进脉冲（硬件定时器）  MCP23017（I²C 设备）  界面后端（串口屏 / 调试屏）  PIN / 中断 │
├────────────── RT-Thread 标准版内核 + 星火一号 BSP ──────────────┤
```

### 4.2 线程划分与通信

| 线程 | 职责 | 优先级（数值越小越高） | 通信方式 |
|------|------|------------------------|----------|
| 安全监测 | 急停、Z 限位、DOCK 红外、运动超时；发现异常立即关闭三路驱动使能并通知其他线程 | 最高 | 由 EXTI 中断释放信号量唤醒，另有 10 ms 周期巡检；通过事件集广播“安全停机” |
| 运动执行 | 执行单个动作序列（旋转 / 升降 / 拨叉），检查每一步的前置条件，到位后复核传感器 | 高 | 从调度线程的消息队列取“动作单”；完成或失败时回送结果 |
| 调度 | 维护任务队列和车位表，选位，把存 / 取任务拆分为动作单 | 中 | 接收人机命令的消息队列；车位表用互斥量保护 |
| 人机 | 解析串口屏上传的触摸事件，刷新车位图、进度和故障信息 | 低 | 串口接收中断 + 消息队列 |
| 后台 | 空闲时预置空托盘、保存车位表快照、心跳 LED | 最低 | 由调度线程投递低优先级任务 |

步进脉冲由硬件定时器中断产生，加减速曲线预先计算成表，不依赖线程调度的实时性。

### 4.3 运动互锁

每个动作执行前，运动线程都要检查前置条件，不满足时拒绝执行并报故障：

| 动作 | 前置条件 |
|------|----------|
| 升降、旋转 | 拨叉处于收回位（收回位开关确认） |
| 空叉伸出 | 处于该层脱开高度，目标车位霍尔检测到托盘 |
| 携盘伸出 | 处于该层啮合高度，目标车位为空 |
| 啮合上抬 | 拨叉在伸出位，车位霍尔检测到托盘 |
| 拉回完成 | 转运台霍尔检测到托盘，**同时**车位霍尔变为无托盘 |
| 任何动作 | DOCK 红外未检测到手；未急停；未超时 |

任何超时、霍尔状态与车位表不一致或限位异常，都会停止后续动作并进入“等待人工确认”状态。急停、断电或复位后，不在位置未知的情况下自动回零。须由操作者在屏幕上确认没有托盘停在交接缝上、拨叉已收回，才允许回零。

### 4.4 车位编址与状态

- 车位地址 = （层 L，方位 D），L ∈ {1, 2}，D ∈ {E, NE, N, NW, W, SW, S, SE}。一层 S 方位为 DOCK，二层 S 方位为竖井，不存车。
- 车位表 `bay[L][D] = {托盘号, 有车}`，另记转运台上的托盘。托盘的有无以霍尔为准，车的有无由用户在 DOCK 确认后记录。
- 标定表 `cal[L][D] = {啮合高度步数, 转角步数}`，保存在 Flash 中，用于补偿甲板挠度和装配误差。

### 4.5 存车与取车流程

**存车**
1. 用户点“存车”。如果 DOCK 已有预置的空托盘，可以直接放车；否则系统调取代价最小的空托盘到 DOCK。
2. 用户放好车，DOCK 红外确认手已离开后，在屏幕上点“确认”。确认前可以取消，空托盘留在 DOCK。
3. 系统把托盘送入代价最小的空车位，更新车位表。
4. 后台再预置一块空托盘到 DOCK，下一位用户无需等待。

**取车**
1. 用户在屏幕车位图上选择车辆。
2. 如果 DOCK 上有预置的空托盘，先把它送回空车位。
3. 取出目标托盘送到 DOCK，用户取车后点“完成”。空托盘留在 DOCK，作为下次存车的预置。

**选位代价**：每换一层计 3 分，每转动 90° 计 1 分，选总分最低的车位。存车时优先选靠近 DOCK 的低层车位，以缩短后续取车时间。

### 4.6 优先级与抢占

- 优先级：**急停 > 取车 > 存车 > 后台预置**。
- 抢占只发生在两个完整动作之间，不在拨叉伸出或托盘跨缝时中断，确保被打断的任务总是处在一个可以确认的稳定状态。
- 用户放车之前可以取消存车。

### 4.7 层数自动识别与标定

- 上电后主控依次扫描 I²C 地址 0x20…0x21：有应答即认为该层存在，按层数生成车位表和屏幕车位图。
- 加装第二层只需装上地址为 0x21 的层检测板，并连上总线和传感器供电线，再用 msh 命令或屏幕的标定页面逐个车位录入啮合高度和转角。
- 扫描到的层数和标定表中的层数不一致时，系统拒绝向未标定的车位存车，并提示进行标定。

### 4.8 人机界面

作品的人机界面是 TJC4827T143 4.3 寸电容触摸串口屏。页面用屏厂的上位机软件设计并下载到屏内，主控通过 USART3 向屏发送刷新指令，并接收屏上传的触摸事件。

| 页面 | 内容 |
|------|------|
| 主页 | 两层车位俯视图（空 / 有托盘 / 有车）、存车、取车按钮 |
| 进度 | 当前步骤（例如“旋转到 2F-NE”）、预计等待时间、取消按钮 |
| 故障 | 故障代码和处理提示；人工确认按钮 |
| 维护 | 点动、回零、标定、传感器实时状态（需密码进入） |

**调试界面**：在转接板和串口屏页面工程完成之前，固件先用星火一号板载的 240×240 LCD 和四个方向键，基于 LVGL 实现一套功能相同的简化界面（空闲、菜单、存车、取车、进度、故障六个页面），用于联调调度、运动和故障流程。它只在开发阶段使用，不是作品的最终界面。

为了让两种屏幕共用同一套业务逻辑，人机线程不直接操作屏幕，而是通过一组统一的“界面后端”接口工作：向上只接收车位状态、任务进度和故障码，向下把用户操作转换成存车、取车、取消、确认等命令。串口屏和调试屏各实现一个后端，切换屏幕不需要修改调度和运动代码。

### 4.9 已完成的仿真验证

- 浏览器三维演示（`docs/cad/assembly-exploded.html`）复现了存取、预置、取消、暂停和急停的完整流程。
- 状态机测试（`tools/test_cad_simulation.js`）：一层和两层配置、开 / 关空闲预置，存满后逐车取出再存回，共 104 个循环。每 0.05 s 检查托盘守恒和全部互锁规则，未发现死锁或违规动作。
- 该测试只验证调度逻辑，不能证明机构、电气或实际定位精度。固件中的调度模块将沿用同一套规则，并用相同的测试用例回归。

## 5 创新点

### 5.1 一台转运装置服务所有层，层模块无电机

- **问题**：常见的升降横移式方案中，电机和驱动器的数量随车位数增加。
- **做法**：升降、旋转和转运 3 个轴集中在中央升降塔上，每层只有甲板、霍尔、LED 和 1 块层检测板。
- **可验证效果**：两层 14 个车位只用 3 台电机。与本团队早期的“每层独立 X/Y 移盘”方案（9 个运动轴，预算约 ¥4,100）相比，运动轴减少到 1/3；两层预算从约 ¥4,100 降到约 ¥1,614（含 15% 机动费）。

### 5.2 用升降动作完成啮合 / 脱开，取消抓取执行器

- **问题**：托盘搬运通常需要电磁铁、舵机或直线执行器来抓取，多一个执行器就多一个故障点和一路控制。
- **做法**：托盘底部装定位销，转运台的 U 形拨叉随升降平台上下 8 mm 进入或离开销的下方。
- **可验证效果**：样机上做拨叉入销、拉回、推出、脱开的连续循环试验，以 100 次循环的成功次数作为评价指标。

### 5.3 I²C 地址即层号，上电自动识别层数

- **问题**：扩容通常需要修改程序和接线。
- **做法**：每层一块相同的层检测板，板上 MCP23017 的地址 = 0x20 + 层号 − 1，各层挂在同一条 I²C 总线上。上电扫描后自动生成车位表，标定数据按层存放在 Flash 中。
- **可验证效果**：演示中在一层运行的系统上加装第二层，重新上电后屏幕自动显示 14 个车位，补录标定后即可使用。

### 5.4 DOCK 空托盘预置 + 取车优先的调度策略

- **问题**：用户存车时，系统常常需要先去取空托盘，造成等待。
- **做法**：每次存车完成后，后台立即把下一块空托盘调到 DOCK；取车请求优先于存车，抢占只发生在动作边界。
- **可验证效果**：DOCK 已有预置托盘时，存车等待为 0。DOCK 为空时，单次取车的预计时间约为 16～21 s（一层）、27～31 s（二层）。该数字由演示状态机按设定速度累加得出，属于估算值。

### 5.5 硬件急停 + 软件分步互锁的双重安全

- **问题**：只靠软件停止脉冲，驱动器仍然带电；只靠硬件切断电源，则无法得知停机原因，也无法安全恢复。
- **做法**：急停和 Z 硬限位直接切断电机支路；逻辑部分保持供电，记录原因。软件对每一步动作检查前置条件，并用传感器复核结果；恢复须人工确认。
- **可验证效果**：演示运动中按下急停、手伸入 DOCK 时，电机立即停止；恢复后不会自动运动。

## 9 小结

本作品以星火一号（STM32F407）和 RT-Thread 标准版为平台，用一台中央升降转运装置服务两层 14 个辐射排列的车位。依靠“升降 8 mm 完成啮合 / 脱开”，省去抓取执行器；依靠“I²C 地址即层号”，层模块可以即插即用。软件上用 RT-Thread 多线程实现优先级调度、空托盘预置和分步安全互锁，硬件急停作为最终保障。目前方案设计、三维建模、引脚分配和调度逻辑仿真已经完成，后续按第 7 节的计划先完成一层样机的验证，再加装第二层，并用实测数据更新本计划书。
